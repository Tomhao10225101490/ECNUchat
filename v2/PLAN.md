# ECNUchat v2 — 全套计划（手机 + 桌面 + 大群组 + 语音 + 推送 + 备份）

用户已选：全套做。来源项目：https://github.com/Tomhao10225101490/ECNUchat
（公开，main 分支，纯 Python，PySide6 桌面 + 终端，WebSocket 服务器本机 127.0.0.1:8765，
X3DH + 双棘轮 + AES-256-GCM + ML-KEM-768 混合，群聊每人一份信封、上限 8 人，
最新提交为一对一加密语音通话。没有手机端、没有多设备、没有生产部署。）

## 核心原则（不能改口的地方）

1. 不推翻现有加密：`protocol.py` 的信封格式冻结为 v1，新旧客户端必须互通。
   改格式就等于把旧 Python 客户端全部断掉。
2. 没有自己的服务器 ≠ 没有中转。中转必须存在，但它只当哑巴邮局：
   只能看到密文信封、公钥、元数据（谁和谁、何时、多大），看不到明文。
   中继地址客户端可改，默认中继挂了可以换，本地加密历史不丢。
3. 私钥不出设备。手机丢了、没有备份，身份就丢了——这是端到端加密的代价，
   必须在界面里明说，不能假装能找回。
4. 没实现的功能要标“未实现 / 占位”，不能写成已实现。特别是：
   抗量子、sealed sender、大群组、iOS 推送，都不能超前宣称。

## 架构

- 中继（Relay）：无状态信箱。只做公钥目录、离线密文暂存、在线转发、
  设备列表。首选部署：Cloudflare Workers + D1/R2 免费层；本地开发用
  同一套逻辑的 Python/Node 本地中继。TLS/WSS 必须开，禁止明文 ws 上生产。
- 客户端共享核心：TypeScript + WebCrypto（AES-GCM）+ libsodium-wasm
  （X25519、Ed25519）。手机 = PWA（GitHub Pages 托管，可装到手机桌面，
  不用上架应用商店）；桌面 = Tauri 套同一个核心。Python 桌面留作参考实现。
- 身份与设备：用户名 3–20 字符（沿用现有规则）。每个设备自己生成密钥，
  身份为 `用户名:设备`。主设备扫码签名给新设备背书；吊销 = 从目录删设备。
  发消息给对方所有设备各一份信封（复用现有每人一份的群聊思路）。
  新设备只收链接后的消息，旧历史不自动同步（见备份节）。
- 发现与加好友：用户名 + 中继地址 + 身份指纹做成二维码/邀请链接，
  扫码加好友，线下核对指纹防中间人。不用手机号、不用短信验证。

## 各模块怎么做

- 大群组：8 人以上不再每人一份双棘轮（消息数爆炸）。改 Sender Keys：
  每人一个群发送链，入群时把自己的 Sender Key 用一对一信封发给成员；
  成员变动、踢人要轮换 Sender Key（这是 MLS 出现之前的务实做法，
  不是完整 MLS；MLS 列为后续研究项，不要谎称已实现 MLS）。
- 语音：文字走中继信箱；语音通话两边在线时走 WebRTC 直连，
  中继只传已加密的信令信封；需要 TURN 时用加密媒体（SRTP），
  TURN 只能看到密文。沿用现有“通话密钥放棘轮信封里”的思路。
- 推送：只唤醒、不带内容。Web Push 发一个空唤醒，客户端自己来取
  密文信封再解密。Android 可用后台 WebSocket/轮询； iOS PWA 推送
  受系统限制，要在文档里如实写清，不能承诺 iOS 和原生 App 一样稳。
- 备份：口令派生密钥（沿用现有 PBKDF2 高迭代思路）加密整份
  身份 + 棘轮状态 + 历史的导出包；可存到中继（密文）、可本地导出文件、
  可扫码迁移。恢复 = 输入口令 + 导入包；没有口令 = 无法恢复。
  备份包本身也是密文，中继读不到。

## 分阶段（全套，但按顺序交付、可验证）

- 阶段 1（先跑通）：中继规范 + 本地中继 + PWA 文字聊天 + 设备分发，
  与现有 Python 客户端互通（文字一对一），测试向量对照现有测试。
- 阶段 2：大群组 Sender Keys + 文件（沿用第二层 AES-GCM 思路）。
- 阶段 3：语音通话（WebRTC）+ 推送（唤醒式）。
- 阶段 4：加密备份/恢复 + 桌面 Tauri 打包 + 部署文档（免费层额度、
  换中继、吊销设备、丢手机怎么办）。

## 绝不能做的事

- 不向 ECNUchat 仓库推送任何东西，除非用户看过构建结果并单独确认。
- 不把任何私钥、口令、demo 密码以外的真实凭证写进代码或文档。
- 不把中继说成“绝对安全”：它仍能看到元数据；要更强需后续做
  sealed sender / 头部加密，那是另一个协议升级，不是顺手能加的。
